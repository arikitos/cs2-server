# GunGame mode — operator guide

A weapon-ladder deathmatch, powered by the **GG2** plugin
([ssypchenko/cs2-gungame](https://github.com/ssypchenko/cs2-gungame), **v1.2.4**)
plus its `GunGameAPI` shared library. Mode id `gungame`, container `cs2-gungame`,
capacity env `GUNGAME_CAPACITY`, mode dir `manager/modes/gungame`.

The mode is isolated: it does **not** load MatchZy, AutoReady, Retakes,
Instadefuse, HeroShift or RayTrace, and normal start / restart / switch never
runs SteamCMD.

## What ships here

```text
modes/gungame/mode.json               # the mode definition the panel reads
modes/gungame/plugins/GG2/            # the plugin that defines the mode (DLLs + lang/{en,ru}.json)
modes/gungame/utils/GunGameAPI/       # shared API other plugins can consume
modes/gungame/cfg/gungame/            # every GG2 setting (mounted to csgo/cfg/gungame)
modes/gungame/cfg/mode_gungame.cfg    # the mode's base ruleset
modes/gungame/cfg/panel_runtime.cfg   # generated by the panel on Apply
```

Every one of those paths is declared in `mode.json`, which is where this mode's
plugin list, capacity range, defaults and RCON quick actions come from, and what
the panel checks under Maintenance → Verify mounts. `PanelBridge` is declared
here too but stays a single shared copy in `manager/shared/plugins/`.

`cfg/gungame/` holds the plugin's own files: `gungame.json` (main settings),
`gungame_weapons.json` (the 23-level CS 1.6-compatible weapon order + kill overrides),
`weapons.json` (per-weapon data), and the `.cfg` hooks GG2 execs itself
(`gungame.warmupstart.cfg`, `gungame.warmupend.cfg`, `gungame.gameend.cfg`,
`gungame.mapvote.cfg`, `gungame.disable_rtv.cfg`). The whole directory is
bind-mounted, so added files need no compose change. Edit on the host, then run
`gg_config gungame` (a panel mode command) to re-read it without a restart.

## Round settings

GG2 needs `game_type 0` / `game_mode 0` (**Casual**), so this is the only mode
that runs `game_alias casual` instead of competitive. `mode_gungame.cfg` then
keeps the round clock out of the way — the weapon ladder decides the winner:
`mp_maxrounds 120`, `mp_timelimit 0`, `mp_roundtime 60`, `mp_freezetime 3`,
overtime off, engine respawn off (GG2's `RespawnByPlugin` owns respawns) and
dropped guns disabled to match `StripDeadPlayersWeapon`.

`mp_warmuptime 60` mirrors `WarmupTimeLength` in `gungame.json` — change both
together. Panel Server Config values live in `data/modes/gungame.json`
(`max_rounds` 120, `freezetime` 3, `bot_quota` 0, friendly fire off, `de_dust2`)
and are written into `panel_runtime.cfg` on Apply.

## Deviations from the stock release

- `gungame.json` → `DisableRtvLevel` **15 → 0**. The stock value execs
  `gungame.disable_rtv.cfg`, which calls `ggmc_nortv` from the *GunGame
  MapChooser* plugin. That plugin is not part of this stack, so the call would
  only log an unknown command.
- `gungame.gameend.cfg` → its single `ggmc_change_nextmap` line is commented out,
  for the same reason. GG2 does not change maps itself; the map is owned by the
  panel (Server Config → map) and applies on the next start / restart.
- `gungame.mapvote.cfg` is left stock but never runs — it is gated behind
  `VoteLevelLessWeaponCount`, which ships at `0` (disabled).

This package uses a CS 1.6-compatible profile rather than the GG2 stock gameplay
values: plugin respawn for both teams, 60-second knife warmup, Turbo mode, 2 kills
per normal weapon, 1 kill for HE/knife, Knife Pro, Glock assistance on the HE
level, classic average-level handicap, and bots allowed to complete the ladder.
CS2-only Molotov/Taser bonus mechanics and the GG2 multi-level bonus are disabled.
Objectives remain removed and silent end/map handling remains enabled because those
are CS2 integration safeguards for this panel-managed profile.

## Stats / ranking (not enabled)

`!rank`, `!top` and `!music` need a database. GG2 reads
`csgo/cfg/gungame-db.json` (`DatabaseType` `sqlite` or MySQL host/port/name/
user/password, plus an optional MaxMind `GeoDatabaseFilePath`), but that file is
**not documented upstream and is not shipped here**, so this profile runs without
it: GG2 logs one "Continue without GunGame statistics" line at load and the
ladder itself works normally. Add the file to `modes/gungame/cfg/` with a
matching compose mount if you want persistent wins/ranks — verify the schema
against the plugin build first.

`GeoLite2-Country.mmdb` (country → language detection) is also not shipped;
`lang/en.json` and `lang/ru.json` are what the plugin has.

## Build and run

```powershell
# Create the service without running SteamCMD.
docker compose create cs2-gungame

# Only one game server may own port 27015 — stop the others first.
docker compose stop cs2-faceit cs2-retakes cs2-superheroes
docker compose up -d cs2-gungame

docker logs -f cs2-gungame   # expect "[GUNGAME] GG Start, version 1.2.4"
```

Prefer the panel: select **GunGame** in Game Mode and press
*Start / switch to selected mode* — it frees port 27015 and writes
`panel_runtime.cfg` for you.

## Commands

| Command | Where | Effect |
|---|---|---|
| `gg_restart` | server console / panel | Restart the GunGame round, everyone back to level 1 |
| `gg_config gungame` | server console / panel | Re-read `cfg/gungame/*.json` |
| `gg_version` | server console / panel | Print the plugin version |
| `gg_enable` / `gg_disable` | server console / panel | Turn the ladder on / off live |
| `gg_reset` | server console | Reset the stats table (needs a database) |
| `gg_respawn <0-4>` | server console | Change respawn handling at runtime |
| `!top` · `!rank` · `!music` | chat | Leaders · own rank · sound toggle (need a database) |
| `!lang <code>` | chat | Switch language (`en`, `ru`) |

The panel exposes the first four plus `bot_kick` as one-click mode commands.

## Rollback

```powershell
docker compose stop cs2-gungame
docker compose rm -f cs2-gungame
```

The shared CS2 installation is untouched; deleting `modes/gungame/` and the
`cs2-gungame` service removes the mode entirely.
