# Retake mode — operator guide

Retakes powered by **RetakesPlugin** (B3none/cs2-retakes) + **Instadefuse**
(B3none/cs2-instadefuse). Mode id `retake`, runtime `cs2-game`, mode dir `manager/modes/retake`.

RetakesPlugin does its own weapon allocation — **no allocator plugin is installed**.
An earlier revision of this mode ran RetakesAllocator alongside it; that was removed
deliberately. If you ever want it back, see "Re-adding an allocator" at the bottom.

The mode is isolated: it does not load MatchZy, AutoReady, HeroShift or RayTrace,
and normal start/restart/switch never runs SteamCMD.

## What ships here

```text
modes/retake/mode.json                      # the mode definition the panel reads
modes/retake/plugins/RetakesPlugin/         # the plugin that defines the mode (+ lang, map_config)
modes/retake/utils/InstadefusePlugin/       # instant defuse when the site is clear (+ lang)
modes/retake/utils/RetakesPluginShared/     # shared API RetakesPlugin exposes
modes/retake/config/RetakesPlugin.json      # RetakesPlugin's own config, deployed over its auto-generated copy
modes/retake/cfg/mode_retake.cfg            # mode extras, on top of shared/cfg/server.cfg
modes/retake/cfg/panel_runtime.cfg          # generated by the panel on Apply
```

Every one of those paths is declared in `mode.json`, which is what the panel
verifies (Maintenance → Verify mounts) and where this mode's plugin list, capacity
range, defaults and RCON quick actions come from. `PanelBridge` is declared here
too but stays a single shared copy in `manager/shared/plugins/`.

## Plugin config

`config/RetakesPlugin.json` is mounted over the copy RetakesPlugin generates on
first boot, so the file in this repo is the single source of truth. Notable values:

- `GameSettings.EnableFallbackAllocation`: **`true`** (the plugin's own default).
  This is what gives players their weapons. It must only be set to `false` when a
  dedicated allocator plugin takes over allocation — with no allocator and this off,
  players spawn without guns.
- `GameSettings.MaxPlayers`: **9**, kept in step with the panel's capacity for this
  mode (`data/modes/retake.json` and `settings.defaults.capacity` in `mode.json`).
  Change all of them together.
- Everything else matches the plugin's auto-generated defaults, copied verbatim.

## Round settings

Retake runs the shared base profile like every other mode: `mode_retake.cfg` execs
`manager/shared/cfg/server.cfg` (`gamemode_competitive.cfg`, `bot_quota 0`,
`mp_autoteambalance 0`, `mp_limitteams 0`, `mp_maxrounds 24`, `mp_freezetime 15`,
`sv_pausable 1`, `mp_restartgame 1`, ...) and then adds the one convar Retake needs
on top of it, `mp_warmuptime 30`. Change a shared value in `server.cfg`, not here.

Panel Server Config values live in `data/modes/retake.json` (`map`, `capacity`,
`max_rounds`, `freezetime`, `bot_quota`, `friendly_fire`) and are written into
`panel_runtime.cfg` on Apply, which execs last and therefore wins. The capacity
range (3-10) and the defaults come from `mode.json`; capacity (9) is the only
default that differs from the other modes.

There is deliberately no `cfg/cs2-retakes/retakes.cfg` here: the buy-menu/economy
cvars that file used to set (`mp_buy_anywhere`, `mp_buytime`, `mp_maxmoney`, ...)
existed only for the allocator and are wrong for plain retakes play.

## Build and run

```powershell
# Create the single stopped runtime without running SteamCMD.
docker compose create cs2-game

# Select Retake in the panel and start/switch it.
docker logs -f cs2-game   # expect RetakesPlugin and Instadefuse load lines
```

Prefer the panel: select **Retake** in Game Mode and press *Start / switch to
selected mode* — it frees port 27015 and writes `panel_runtime.cfg` for you.

## Commands

Panel quick actions, all whitelisted in `mode.json`:

| Command | Effect |
|---|---|
| `css_forcebombsite A` / `B` | Force future rounds onto one bombsite |
| `css_forcebombsitestop` | Return bombsite selection to the plugin |
| `css_scramble` | Reassign connected players between teams |
| `css_debugqueues` | Print the current retake queue |

Admin flags for each are set in `config/RetakesPlugin.json` under
`CommandsSettings`, along with the map-config and spawn-editor commands
(`css_mapconfig`, `css_showspawns`, `css_addspawn`, ...) which stay `@css/root`.

## Re-adding an allocator

If round-type weapon allocation is ever wanted again
(yonilerner/cs2-retakes-allocator): drop the release's `RetakesAllocator` folder in
`utils/`, declare it in `mode.json` (`role: "util"`, target
`addons/counterstrikesharp/plugins/RetakesAllocator`), add the matching bind mount
in `compose.yml`, set `EnableFallbackAllocation` back to `false`, and re-add the
buy-menu cvars in `cfg/cs2-retakes/retakes.cfg`. Its binaries are not distributed
in this repo.

## Removing the mode

Switch away from Retake first, then remove `manager/modes/retake/` and
restart the panel. The next mode deployment removes Retake's inventory-owned
files while leaving the shared CS2 installation and unmanaged plugins untouched.
